# 更新日志 / Changelog

本文件记录 VSManager 的主要变更，格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循[语义化版本](https://semver.org/lang/zh-CN/)。
All notable changes to VSManager are documented here. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows [Semantic Versioning](https://semver.org/).

## [未发布 / Unreleased]

### 新增 / Added
- 新增只读工具 `read_agent_chat`：按轮列出 AI 对话（时间、脱敏的消息摘要、该轮实际调用的工具名），并列出本进程与历次启动读回的执行计划及「执行计划恢复」通知是否发出；`plan.log` 每次启动都记录读回情况（含 0 个）与进程号，单独发出的恢复通知也写入日志。系统提示词加入「对话核对」说明。
  New read-only tool `read_agent_chat`: lists AI chat rounds (time, redacted message summary, tools actually called) and the execution plans read back by this and earlier startups, with whether the "Plan resumed" notice was sent; `plan.log` now records every startup (even with 0 plans) with its process id, and separately sent resume notices are logged too. The system prompt gains a "Chat checks" note.
- 执行计划缓存：新增 `create_plan` / `update_plan_step` / `read_plan` / `complete_plan` 工具与系统提示词规则 20，复杂流程自动建计划并持久化到 `%APPDATA%\VSManager\agent-plans.json`，重启后自动读回并通知 AI 接着执行，全部完成才释放；`read_restart_handoff` 同时显示常驻的计划文件状态，日志写入 `plan.log`。
  Execution plan cache: new `create_plan` / `update_plan_step` / `read_plan` / `complete_plan` tools and prompt rule 20; complex flows get a plan persisted in `%APPDATA%\VSManager\agent-plans.json`, read back after a restart with a notice so the AI continues, and released only when complete; `read_restart_handoff` also shows the resident plan file and events go to `plan.log`.
- AI 总控助手新增只读工具 `read_vsmanager_log`（name / lines / date）：读取 `%APPDATA%\VSManager\archive\logs` 与 `%APPDATA%\VSManager\logs` 下的 VSManager 日志，返回路径、总行数与末尾 N 行脱敏原文，用于核对测试项要求的日志记录；提示词（中英）已说明用法，`agent.log` / `file-audit.log` 不开放。
  New read-only AI assistant tool `read_vsmanager_log` (name / lines / date): reads VSManager logs under `%APPDATA%\VSManager\archive\logs` and `%APPDATA%\VSManager\logs` and returns the path, total line count and the last N lines redacted, for checking log records named by test items; the prompt (zh / en) explains it; `agent.log` / `file-audit.log` stay closed.
- AI 架构优化：总控助手工具按需加载。每轮只公布核心工具，其余 7 个工具组（布局、自测、检查、worktree、笔记、CAD、MCP）按本轮文字、近 8 轮使用或新元工具 `load_tools` 加入，未公布的工具仍可按名调用；普通一轮的工具定义从约 6.3 万字符降到约 2 万字符（75 → 29 个）。可在属性中关闭，默认开启。
  AI architecture: on-demand tools for the manager assistant. Each round advertises only core tools; the 7 other groups (layout, self-test, inspection, worktree, notes, CAD, MCP) join by the round's text, use in the last 8 rounds or the new `load_tools` meta tool, and unadvertised tools stay callable by name. A plain round's tool definitions drop from about 63k to about 20k characters (75 → 29 tools). Can be turned off in Properties; on by default.
- 任务自动接续：任务返回待验证或部分完成时，AI 助手自动判断剩余步骤，用新工具 `continue_task` 向同一 VS 发布只做剩余步骤的接续任务，不停下来等用户（每个任务接续一次、每条链最多 3 次；原任务阻塞时自动放行；属性中可关闭，默认开启）。提示词新增第 19 条，完成通知附「[自动接续]」说明。
  Task auto-continue: when a task returns awaiting verification or partially done, the AI assistant works out the remaining steps and publishes a continuation covering only them to the same VS with the new `continue_task` tool instead of waiting for the user (one per task, at most 3 per chain; a blocking original is released; can be turned off in Properties, on by default). Prompt rule 19 added; completion notices carry an "[自动接续 / Auto-continue]" block.

### 修复 / Fixed
- 测试项可验证性重判的日志从未写出：启动时只在结论改变时记录，而清单在进入待验证时已重判过，启动时几乎不会再改变；进入待验证时的重判则完全没有日志。现在任务进入待验证时在 `tasks.log` 写入「任务 #N 进入待验证：已按测试项文字重判 N 个测试项的可验证性（其中 M 项改变）」，启动时只要重判过项目也会写入同样的记录。
  The verifiability re-judge was never logged: at startup it logged only when a verdict changed, but checklists are already re-judged on entering verification so startup almost never changes anything, and the re-judge on entering verification had no log at all. Entering verification now writes "Re-judged the verifiability of N test item(s) from their text (M changed)" to `tasks.log`, and startup writes the same record whenever it re-judged items.
- 发送日志里看不到发布任务时附加的「【执行方式】请按自动推荐的提示词执行」：发送过程只截取正文开头 80 字，而这段规则附在正文末尾。现在在「任务清单：发布任务 #N」之后另起一行，写入正文字数与附加的执行方式全文。
  The "【执行方式】请按自动推荐的提示词执行" rule appended on dispatch never showed in the send log: the send trace keeps only the first 80 characters and the rule sits at the end. A line after "任务清单：发布任务 #N" now records the text length and the full appended rule.
- 测试项可验证性重判误判元测试项：描述其他项标注的项（如「list_test_checklists 中『窗口位置 / 草稿』类显示为 [AI]、『动画 / 颜色 / 点击按钮』类显示为 [人工]」）因引号里的「动画 / 点击按钮」被判成 [人工]。现在提到清单工具或「显示为 / 标为 [AI] / [人工]」的元测试项忽略引号内的引用词，本项自身无人工动作即判 [AI]；已有清单在启动与读取时自动更正。
  Verifiability re-judging misjudged meta items: an item describing other items' tags (e.g. "in list_test_checklists, items like 'window position / draft' show as [AI] and 'animation / colors / click button' as [人工]") became [人工] because of the quoted words. Meta items that mention a checklist tool or "show as / tagged [AI] / [人工]" now ignore quoted citations and are [AI] unless the item itself needs a human action; existing checklists are corrected at startup and when read.
- 自测重启后页面与选中的 VS 未按 `restart-ui.json` 恢复：原先恢复只在启动时切一次页面，一旦 AI 总控页被打开就放弃选中 VS；现在重启后 20 秒内保持保存的页面与选中 VS（被程序切走会改回并记日志，用户手动点选则停止），`get_window_state` 在不一致时给出最近一次页面切换的来源。
  After a self-test restart the page and selected VS were not restored from `restart-ui.json`: the restore switched the page only once at startup and gave up selecting the VS as soon as the AI page was shown. For 20 seconds after a restart the saved page and VS are now held (program switches are reverted and logged, a manual user pick stops it), and `get_window_state` reports the source of the last page switch when they differ.
- 重启场景草稿丢失：`prepare_restart_scenario` 再次调用会整体替换上一次场景，先设的草稿随之丢失；现在多次调用合并。场景切到 VS 对话页时同步切页，不再误报「仍停在 AI 总控页」；重启前重新写入草稿时不覆盖用户新输入的文字。
  Lost restart-scenario draft: a second `prepare_restart_scenario` call replaced the whole earlier scenario, dropping a draft set first; repeated calls now merge. Switching the scenario to a VS chat page is synchronous, so "still on the AI page" is no longer misreported; re-writing the draft before a restart never overwrites new user text.

### 变更 / Changed
- 每个发布的任务在回执规则前附加「【执行方式】请按自动推荐的提示词执行」：出现自动推荐的提示词时直接按推荐内容推进到完成，不停下来等确认；确实无法继续时才停下并说明需要什么。
  Every published task now carries an execution rule before the receipt rules: follow the automatically suggested prompts and drive the task to completion without stopping for confirmation; stop only when truly blocked and say what is needed.
- AI 总控助手提示词新增第 18 条：用户不在、无法回答提问时不停下来等待，自己做出决策把任务推进到完成并说明所做决定；只有确实无法继续时才停下，并在最终回复中明确需要用户提供什么（授权类限制照常有效）。
  AI assistant prompt rule 18: when the user is away and cannot answer, the assistant no longer stops to wait but decides itself, drives the task to completion and states its decisions; it stops only when it truly cannot continue and then says clearly in the final reply what the user must provide (authorization limits still apply).
- 无感重启：重启 VSManager 时忽略其他 VS 中正在执行的任务，不再等待它们或排队的助手通知；等待期间其他 VS 的完成事件暂缓，未处理通知写入 `%APPDATA%\VSManager\restart-notices.json` 并在新进程中补发，执行中任务由新进程继续跟踪、不重发。提示词与 `restart_vsmanager_for_testing` 说明同步更新。
  Seamless restart: restarting VSManager ignores tasks running in other VS instances and no longer waits for them or for queued assistant notices; their completion events are deferred while waiting, unprocessed notices are saved to `%APPDATA%\VSManager\restart-notices.json` and re-delivered by the new process, and running tasks keep being tracked without resending. The prompt and the `restart_vsmanager_for_testing` description are updated.
- AI 总控助手提示词：向 CAD 测试环境项目（如钢筋等 CAD 插件项目）发布任务时，在任务文字中注明不需要目标 VS 启动 CAD 自行测试，CAD 测试由 ai.agent 后续完成。
  AI assistant prompt: tasks published to CAD test-environment projects (CAD plug-ins such as a rebar plug-in) now state that the target VS need not start CAD to test; ai.agent runs the CAD tests afterwards.
- AI 总控助手新增补 skill 闭环 `start_skill_gap_loop`：测试项用现有工具验证不了、但新增 skill 可自动验证时，由 AI 自动发起「发布实现任务 → 重启加载 → 用新 skill 验证 → 勾选或带证据修复」，复用自迭代状态与轮次上限（默认 3）；目标项记录所补 skill，允许 AI 用它勾选（必须人眼 / 人手的项除外），每项只发起一次；自动验证通知与提示词写明闭环规则及其与自迭代的关系。
  Added the skill-gap loop `start_skill_gap_loop` for the AI assistant: when existing tools cannot verify an item but a new skill could, the AI itself runs publish → restart → verify with the new skill → check or fix with evidence, reusing the self-iteration state and round limit (default 3); the target item records its skill so the AI may check it (except items needing human eyes or hands), one loop per item; the auto-verify notice and the prompt describe the loop and how it relates to self-iteration.
- AI 总控助手新增测试项可验证性自动重判、自动验证与场景补齐：待验证时（及启动 / 读取已有清单时）按文字把界面探测可读的项（窗口位置 / 大小 / 最大化 / 屏幕、页面、选中的 VS、草稿、托盘与残影、前台焦点、交接文件）改为 [AI]，观感、动画、颜色、点击按钮、人为制造故障保持 [人工]；AI 发布的任务完成通知附「[自动验证]」说明；新增 `prepare_restart_scenario` 造出重启前场景（页面、VS、草稿、窗口状态、屏幕、前台），自测重启前再应用一次并写进重启完成通知；提示词同步说明。
  The AI assistant gains checklist re-judging, auto-verification and scenario setup: on awaiting verification (and at startup / when reading existing checklists) probe-readable items (window bounds / maximized / screen, page, selected VS, draft, tray and ghosts, foreground, handoff files) become [AI], while looks, animation, colors, button clicks and deliberate failures stay [人工]; completion notices of AI-published tasks carry an "[自动验证 / Auto-verify]" block; new `prepare_restart_scenario` sets up the pre-restart scenario (page, VS, draft, window state, screen, foreground), re-applied before the self-test restart and recorded in the restart notice; the prompt documents it.
- 测试清单分为「AI 可验证」（青绿色 AI 标签）与「必须人工验证」（琥珀色 人工 标签）两类：回执规则要求 Copilot 为每项标注 [AI] / [人工]，未标注时保守推断；新增「🤖 AI 验证」按钮与「🔁 自验证」循环开关（`AgentSelfVerify`），自动让 AI 助手验证、勾选 AI 项并带证据重试未通过项；`mark_test_item` 拒绝勾选人工项。
  The test checklist is split into AI-verifiable (teal "AI" tag) and manual (amber "人工" tag) items: the receipt rules ask Copilot to tag each item [AI] / [人工], with conservative inference when untagged; added an "🤖 AI verify" button and a "🔁 Loop" self-verify switch (`AgentSelfVerify`) that has the AI assistant verify and check AI items and retry failures with evidence; `mark_test_item` refuses manual items.
- 新增 AI 总控助手自迭代循环：`start_self_iteration` / `stop_self_iteration` 在用户明确要求时记录目标与轮次上限（默认 3，最多 10），助手循环「发布任务 → 完成 → 自测重启 → 测试并勾选 → 修复或结束」；重启通知附带本轮说明，达到上限拒绝重启，调试 VSManager 的 VS 仍有执行中任务时不重启。
  Added a self-iteration loop for the AI assistant: `start_self_iteration` / `stop_self_iteration` record a user-requested goal and round limit (default 3, max 10); the assistant loops publish → complete → restart for testing → mark items → fix or stop. The restart notice carries round guidance, restarts are refused at the limit and while the VS debugging VSManager still runs a task.
- CAD 调试自动加载 DLL 修复 FILEDIA=0 时无法加载的问题：点击调试时 VSManager 检查启动程序对应的 AutoCAD 配置，FILEDIA（注册表 `FileDialog`）为 0 时在启动前改为 1 并在状态栏说明；启动脚本首行再以 `(setvar "FILEDIA" 1)` 兜底，其他 CAD 宿主同样生效。
  CAD debug auto-load now works when FILEDIA is 0: on Debug, VSManager checks the AutoCAD settings of the start program and changes FILEDIA (registry `FileDialog`) from 0 to 1 before launch, noting it in the status bar; the first startup-script line sets FILEDIA back to 1 as a fallback, covering other CAD hosts too.
- CAD 自验证新增「ai.agent → ai.exe → 目标项目验证接口」链路：新增可嵌入目标项目的验证 SDK `VSManager.Verify`（程序目录 `sdk\VsmVerify.cs`，本机命名管道 `VSManager.Verify.<进程ID>`，仅当前用户、拒绝网络登录），ai.exe 新增 `verify list / verify run`，AI 总控助手新增 `list_verify_checks` 与 `run_verify_check`（按调试附加进程或解决方案名匹配端点，遵循操作前确认，只有 pass 才可勾选测试项）；系统提示词在有检查项时优先使用该接口，否则沿用 `run_cad_actions`。
  CAD self-verification gains an "ai.agent → ai.exe → target-project verification interface" chain: an embeddable verification SDK `VSManager.Verify` (`sdk\VsmVerify.cs` in the program folder; local named pipe `VSManager.Verify.<pid>`, current user only, network logons denied), ai.exe `verify list / verify run`, and the assistant tools `list_verify_checks` and `run_verify_check` (endpoints matched by debugged process or solution name, confirmation honored, only pass may tick a test item). The system prompt prefers them when checks exist and otherwise keeps `run_cad_actions`.
- 屏幕布局一并安排 VS 的其他窗格：`place_workspace_windows` 新增 `solutionExplorer`，`arrange_workspace_layout` 默认同时布局错误列表与解决方案资源管理器（新增 `includeSolutionExplorer`）；「屏幕布局 / Layout」快捷按钮与系统提示词要求为每个 VS 安排 Copilot、输出、错误列表与解决方案资源管理器；尚未创建的内置窗格按 GUID 创建，还原时恢复原来的隐藏状态。
  Screen layout now arranges the other VS panes too: `place_workspace_windows` accepts `solutionExplorer`, and `arrange_workspace_layout` includes Error List and Solution Explorer by default (new `includeSolutionExplorer`); the "屏幕布局 / Layout" quick button and the system prompt ask for Copilot, Output, Error List and Solution Explorer for every VS; built-in panes not yet created are created by GUID and hidden again on restore.
- AI 总控助手新增自测重启技能：`restart_vsmanager_for_testing` 在 VSManager 于 VS 调试器中运行时，先把项目预编译到临时目录，本轮对话结束且没有发送中的任务后保存任务清单、配置、笔记与本会话启动授权并写入 `%APPDATA%\VSManager\restart-handoff.json`，再让该 VS 重新启动调试；新进程读取交接单恢复授权、接续对话，并发送「[重启完成通知]」让助手按测试计划续跑工具可验证的测试。新增 `mark_test_item` 按工具依据勾选待验证任务的测试项。重启期间其他 VS 中的任务继续执行、重启后继续跟踪，不重复发布；VS 未重启时自动撤销并告知助手。
  Adds a self-test restart skill to the AI assistant: when VSManager runs under a VS debugger, `restart_vsmanager_for_testing` pre-builds the project into a temp folder, then after the round ends and no send is in flight saves tasks, settings, notes and session start grants to `%APPDATA%\VSManager\restart-handoff.json` and has that VS restart debugging; the new process restores grants, resumes the conversation and sends a restart-completed notice so the assistant continues the tool-verifiable parts of the test plan. New `mark_test_item` checks checklist items with tool evidence. Tasks in other VS instances keep running and are tracked again after the restart without being resent; if VS does not restart, the attempt is withdrawn and reported.
- AI 总控助手新增会话层隔离（`AgentSessionIsolation`，默认开启，属性中可关闭）：模型上下文按项目（解决方案名）分轮归属，任务通知归属其项目，用户消息恰好提到一个项目时归属该项目；项目轮只看到全局对话与本项目对话，并被提示不得混用其他项目的结论、文件路径与错误信息，全局轮只看到全局对话与各项目最近结论摘要；归属写入 agent-chat.jsonl，重开后接续。界面对话保持一条，排队与调度规则不变。
  Adds session-level isolation to the AI assistant (`AgentSessionIsolation`, on by default, can be turned off in Properties): the model context is attributed per round to projects (solution name); task notices belong to their project and a user message mentioning exactly one project belongs to it. Project rounds see only the global and that project's conversation and are told not to mix in other projects' conclusions, file paths or errors; global rounds see the global conversation plus each project's latest conclusion digest. Scopes are stored in agent-chat.jsonl and resumed on reopen. The on-screen transcript stays one thread; queueing and dispatch rules are unchanged.
- 修复钢筋等项目中 Copilot 对话窗格停留在聊天历史列表时任务一直发不出去：历史列表视图没有对话列表元素，窗格搜索把它当成「未找到窗格」，自动打开只执行显示命令、从不点「返回」，结果被误报为「无法确认目标输入安全」并每隔几秒原样重发。现在窗格搜索能识别历史列表视图并自动点「返回」；自动修复后仍未就绪时返回带诊断原因的「等待对话窗格就绪」（未找到窗格 / 不可见 / 历史列表 / 无输入框 / 定位不到输入框，含处理建议），任务清单按「诊断 → 修复 → 间隔 10 秒、30 秒重试」最多 3 轮，仍失败就停止自动重发并以该原因失败；AI 总控助手收到这类失败时先调用 open_copilot 修复并确认成功再重试，否则把原因转告用户。
  Fixed tasks never being sent when a project's Copilot chat pane was left on the chat history list: that view has no conversation list element, so the pane search reported "pane not found", auto-open only ran the show command and never pressed Back, and the result was misreported as "cannot confirm safe target input" and resent unchanged every few seconds. The pane search now recognizes the history view and presses Back automatically; if the pane is still not ready after the repair, the send returns a diagnosed "Chat pane not ready" result (not found / offscreen / history list / no input / input not located, with a remedy). The task list follows "diagnose → repair → retry after 10 s, 30 s" for at most 3 rounds, then stops resending and fails with that reason; the AI assistant first calls open_copilot and retries only after it succeeds, otherwise it relays the cause to the user.

- **查看全部测试清单**：AI 总控助手用 `list_test_checklists` 查看全部待验证任务的完整测试清单（不再只看到最近的两三条），`list_tasks` 也会列出所有待验证任务并为测试项编号；旧任务的清单从已保存的回复补齐。提示词说明这是只读查询、不能为此发布任务：清单保存在 VSManager 自身，各 VS 中的 Copilot 看不到，发布只会产生无效任务；工具不足时也须先说明原因、经用户确认才可请求完善能力。
  **View every checklist**: the AI assistant uses `list_test_checklists` to see the full checklist of every task awaiting verification (not just the two or three most recent), and `list_tasks` now includes every such task with numbered items; older tasks are filled from the saved reply. The prompt explains this is a read-only query that must not become a published task: the checklist lives in VSManager and the Copilot in each VS cannot see it, so publishing would only create a useless task; when tools fall short it must explain why and ask for an improvement only after the user confirms.

  **Smoother restart**: the self-test restart and the Restart button save window position, size, maximized/minimized state, current page (AI assistant or a VS chat), selected VS and the AI input draft to `%APPDATA%\VSManager\restart-ui.json` (used once, valid 15 minutes). The new process restores them in place (default placement if that screen is gone) and no longer forces the AI assistant page; if the window was not in the foreground, the new one does not steal focus. When it was in the foreground, a screenshot of the old window covers the rebuild gap (labelled "正在重启 / Restarting") and disappears once the new window shows; the tray icon is removed first so no ghost icon remains; resuming the conversation waits for the instance list to refresh (2–8 s).

### 修复 / Fixed

- 点击任务清单 / VS 列表中最后一项下方的空白处时会选中最后一项（原生列表框按最近条目处理点击）：现在左键空白处保持原选中项，右键空白处清除选中，右键菜单不再作用于最后一项。
  Clicking the blank area below the last item of the task list / VS list selected the last item (the native list box maps clicks to the nearest item): a left click on blank space now keeps the current selection and a right click clears it, so the context menu no longer acts on the last item.
- 推送任务时未核实结果就提示成功：之前只要调用了入队就返回「已加入任务清单」，即使任务未保存、不在清单中或始终未送达。现在入队后先核实任务确在清单中且已保存，再跟踪最多 30 秒：确认送达 Copilot 才返回「✅ 推送成功」；发送失败返回「❌ 推送失败」及原因；暂未发送（等待开始、队列暂停、前序任务、目标忙碌 / 未打开、手动对话礼让或超时）返回「⏳ 已加入任务清单，尚未推送」及原因。主控 AI、网页远程与内置对话均按此结论提示。
  Pushes were reported as successful without checking: enqueueing always returned "added to the task list", even when the task was not saved, not listed or never delivered. Enqueueing now first verifies the task is listed and saved, then tracks it for up to 30 s: only a confirmed delivery to Copilot returns "✅ 推送成功 (pushed)"; a send failure returns "❌ 推送失败 (push failed)" with the reason; a task not being sent yet (awaiting Start, queue paused, predecessor, target busy / closed, manual-chat yield or timeout) returns "⏳ queued, not yet pushed" with the reason. The main AI, web remote and built-in chat all report this verdict.
- 带截图的任务推送失败（「所请求的剪贴板操作失败」）：部分剪贴板同步 / 云桌面程序会在 OLE 写入剪贴板后占用它数秒，图片路径连续写入文字与图片时第二次写入被拒。现在改用 Win32 直接写入（文字与 CF_DIB / PNG 图片），占用时最多等待 5 秒；仍被占用时任务保持排队稍后重试，不再直接判失败。纯文字发送也会完整恢复用户原有的剪贴板内容（包括截图），不再把截图清空。
  Tasks with screenshots failed to send ("requested clipboard operation failed"): some clipboard sync / cloud desktop agents hold the clipboard for seconds after an OLE write, so the second write (text, then image) was rejected. Writes now go through Win32 directly (text and CF_DIB / PNG images) and wait up to 5 s for a busy clipboard; if it stays busy the task stays queued and retries instead of failing. Text-only sends also fully restore the user's previous clipboard, screenshots included, instead of clearing it.
- Copilot 在回执后附加「(This turn has no user-facing reply.)」之类占位说明时任务被误判为缺少回执：识别回执前忽略末尾的这类说明，回执规则也要求回执行之后不再输出任何文字。
  Tasks were misjudged as missing a receipt when Copilot appended a placeholder such as "(This turn has no user-facing reply.)" after it: such trailing notes are now ignored, and the receipt rule asks for nothing after the receipt line.

- 输入框 @ 候选弹层不再频闪：定时刷新时候选未变化则不重建列表、不重设选中项与位置，且弹层首次显示即定位到光标处。
  The @ mention popup no longer flickers: periodic refreshes skip rebuilding unchanged candidates, selection and bounds, and the popup opens at the caret on first show.

- 打开 VSManager 后 Visual Studio 明显卡顿：Copilot 忙碌探测每 1.5 秒对每个 VS 的整棵 UI Automation 树做后代搜索（实测每个 VS 每轮 3–6 秒，由 VS 界面线程响应）。现在复用已缓存的对话窗格，只在窗格直接子元素中查找停止 / 发送按钮与附件列表（约 30–40 毫秒）；仅在子级找不到时才每 30 秒深度搜索一次，未找到窗格时的完整搜索冷却由 10 秒逐步延长到 30 秒。
  Visual Studio lagged noticeably while VSManager was running: the Copilot busy probe ran a descendant search over each VS's entire UI Automation tree every 1.5 s (measured at 3–6 s per VS per round, served by the VS UI thread). The probe now reuses the cached chat pane and looks for the stop / send buttons and the attachment list among the pane's direct children only (about 30–40 ms); a deep search runs at most every 30 s when no child match exists, and the full search cooldown for a missing pane grows from 10 s to 30 s.

- 向 Copilot 发送任务时误报「未能确认消息已粘贴到 Copilot 输入框」：对话中含代码块时，代码块（同为 WpfTextView）被当成输入框，导致无法聚焦、粘贴落空并连续失败。现在只在输入框宿主 WpfTextViewHost 下查找；粘贴确认改为规范化比对（换行、空白、全角半角、零宽字符）、带退避的轮询与可配置超时，失败时区分「没写进去 / 仍在粘贴 / 内容不一致 / 无法读取」，自动重试一次并在发送日志中记录诊断信息。
  False "could not confirm the message was pasted into the Copilot input box" errors: when the conversation contained a code block, the code block (also a WpfTextView) was taken for the input box, so focusing and pasting failed repeatedly. The input is now looked up only under its WpfTextViewHost; paste confirmation uses normalized comparison (line breaks, whitespace, full/half width, zero-width characters), back-off polling with a configurable timeout, distinguishes "not written / still pasting / different content / unreadable", retries once automatically and writes diagnostics to the send log.
- 上一项修复后偶发连续报「未找到 Copilot 输入框」：长回合结束后窗格的 UI Automation 树暂未刷新，而重试仍复用缓存的窗格、只在控件视图中查找且不记录原因。现在按 L1 WpfTextViewHost → L2 对话列表外最靠下的 WpfTextView → L3 最靠下的可编辑文本元素 → L4 旧方式（校验可编辑）→ L5 位置命中测试分层降级，每级记录诊断；带退避轮询并在每次轮询时丢弃缓存重新查找窗格，失败后重新打开窗格自动重试一次；区分「窗格未找到 / 输入框未找到 / 输入框不可编辑」并给出可操作提示。
  Intermittent repeated "Copilot input box not found" after the fix above: after a long turn the pane's UI Automation tree was not refreshed yet, while the retry reused the cached pane, searched only the control view and logged no reason. The input is now located through a layered fallback L1 WpfTextViewHost → L2 lowest WpfTextView outside the conversation list → L3 lowest editable text element → L4 legacy lookup (editability checked) → L5 hit test, with diagnostics per level; polling backs off and re-finds the pane without the cache on every poll, then reopens the pane and retries once; "pane not found / input not found / input read-only" are reported separately with actionable hints.
- 调用 DTE 命令前就记录 VS 是否在前台，使后台发送后切回原窗口的逻辑在命令把 VS 切到前台时也能生效。
  Whether VS was in the foreground is now recorded before any DTE command, so background sending switches back to the previous window even when the command brought VS forward.
